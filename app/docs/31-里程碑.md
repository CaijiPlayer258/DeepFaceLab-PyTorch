## 2026-11-10 · 对齐脸写盘改成真 4:4:4（cv2 5.0 静默降级的坑）

- 修：`write_dfljpg(..., subsampling=0)` 在 cv2 5.0 上被拒（`IMWRITE_JPEG_SAMPLING_FACTOR`
  只认 `ImwriteJPEGSamplingFactorParams` 枚举），**imencode 照样返回 True、静默落成 4:2:0**；
  老代码那句 `except AttributeError` 兜不住「常量在、值错了」。实测 `data_src/aligned`
  **1203/1203 全是 (2,2)**，切脸阶段写的 `subsampling=0` 从来没生效过（带不带这个参数
  编出来的字节完全相同、还每张刷一句 fallback warning）
- 现在：`_align.jpeg444_probe()` 一次探测（枚举常量 → **按落盘字节的 SOF 头核对**，不硬编码数字），
  结果缓存、之后不再打日志；拿不到 4:4:4 时 WARN **一次**并写清后果（色度被抽稀）。
  `write_dfljpg` 默认 4:4:4，`subsampling=None` 留作「库默认 4:2:0」的对照口
- 顺带：分段导出 jpg 帧共用同一份探测（`_stage_imencode` 删掉自己那份 try/except）
- 数字（cv2 5.0.0）：老数据当输入体积 **+21.5%**；新鲜裁剪（提取器真正的输入）
  **+29.0%** 体积 / 整体 PSNR **+1.66 dB** / 色度 **+2.24 dB** / 第二代色度 **+2.50 dB**。
  别拿老 4:2:0 当基准 —— 那是这套滤波的不动点，量出来的「444 更差」是假象
- 兼容：老 4:2:0 与新 4:4:4 混放，引擎 `DFLJPG.load` / `get_landmarks` / `cv2.imread`
  33/33 全过；**不建议**把老数据另存成 4:4:4（体积 +21.5%、信息 +0）
- 验收：`app/tools/accept/aligned444_accept.py`（`PASS 38 · FAIL 0`，含 PIL 与 ffmpeg `yuvj444p`
  两份外部证据）；`stage6_accept` 回归 **PASS 64 · FAIL 0**（63.1 s）
- 说明与取舍写进 `app/docs/notes/aligned-jpeg-444.md`

## 2026-10-25 · 提取器完工

- 检测器双档：**高精度 RetinaFace_10g** / **高性能 TinyMog**（谁的档位谁负责，不跨档兜底）
- 对齐：动态分辨率（边长 = 检测框长边 × 2，无上下限），越界填纯黑
- 流水线：解码 → 检测 → 对齐/编码/写盘三级并行，1080×1920 源实测 84~93 帧/秒
- 帧跳跃语义修正：**1 = 逐帧**（不再挂 fps 滤镜）；N = 隔 N-1 帧取 1 帧
- 四格实时统计：帧速度 / 人脸速度 / 已对齐人脸 / 已处理帧
- 数据集过滤器：清晰度 / 噪点 / 曝光 / 遮挡（hull 与 XSeg 差值）/ 重复图
