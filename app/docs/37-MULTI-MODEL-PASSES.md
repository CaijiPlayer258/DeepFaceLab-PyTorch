# 37 · 多模型分趟导出（人脸暂存池 / 闸门 / 落盘）

> 场景：N 个 dfm 给 N 张脸换脸。8GB 卡上「每个模型一份会话 × 每条 lane」必炸，
> 所以改成 **分趟 + 人脸暂存池 + 一次性合流**。单模型（N=1）不走这条路，保持现有稳态流水线。

## 1 · 为什么不是「多开 lane」，也不是「合成完再合成」

```
每帧 N 张脸 → 若分属 N 个模型，就是 N 次前向（单次 18~21ms）
  10 模型 10 脸 → 200ms/帧 → 上限 5 fps   ← 这是**算法下界**，显存怎么优化都绕不开
所以优化目标不是「装下 10 个模型」，而是「让每次前向尽量多装几张脸」
  → 分趟：一趟只装一个模型，把它名下的脸一次跑完（批内 8 张）
```

也 **不做** 「先合成 A，再把 A 的成品喂给 B 合成」：那是混合 N 次，seamless（Poisson）与
hist-match 的参考像素会变，结果与「一次合成」不等价，逐帧对拍必然对不上。

## 2 · 三相位

```
Pass 0  扫描      解码 → 检测 → 68 点 → embedding → 分配表（落盘）
Pass k  模型 k    只装模型 k → 跑它名下的脸 → 写「脸原料」到磁盘
Final   合流      闸门开 → 多线程顺序读回 → 每帧一次 compose → 编码一次
```

## 3 · 人脸暂存池（落盘）

```
<视频>_cache/pool/
    index.json          脸清单：帧号 / 脸序号 / bbox / mat / 所属模型 / chunk 偏移
    chunks/0000.bin     相邻 16 帧的脸原料合批（减少 seek）
```

单脸原料（无 XSeg 时后两张不存在）：pred (S×S×3 u8) · prd_dfm (S×S u8) · xseg_prd · xseg_dst。
约 0.5MB/脸（有 XSeg）、0.2MB/脸（无 XSeg）。

**为什么按 chunk 合批**：1439 帧 × 1.5 脸 ≈ 2000+ 个小文件，机械盘上光 seek 就拖死；
chunk 化后约 90 个文件，顺序读能吃满带宽。

## 4 · 分母（水池最大容量）—— 动态增长

```
分母 = **待换脸的脸数**（检测到 且 embedding 匹配上人脸库某个组）
     ≠ 检测到的总脸数（不匹配的脸不进水箱，它们不会被换）

Pass 0 期间：分母随扫描增长 → UI **不显示百分比**（否则会往回跳）
Pass 0 结束：分母冻结，之后只涨水位
```

## 5 · 闸门与读回

```
闸门关闭：趟 k 还在写盘；loader 不启动；合成线程 wait
闸门开启：一次性启动 loader 池（默认 4 线程，队列 = 合成线程数 × 2）
          合成按**帧号顺序**抽水 → 重排缓冲窗口 64 帧 → 编码
```

顺序抽水必须显式保证：随机顺序会打乱编码器输入顺序。重排缓冲复用快速导出里那套按帧号重排。

## 6 · 前端视图（定稿）

```
 解码      TinyMog#0      阿証-416#0     XSegLite#0      人脸暂存池     闸门      合成           h264_nvenc#0
```

- 节点名用**真实名字**：`<检测器>#<lane>` / `<模型>#<lane>` / `<遮罩来源>#<lane>`；
  合成 `合成#0..#7`，编码 `h264_nvenc#0..#2`。这几格**不再要副标题**。
- 人脸暂存池：**竖直**池子，标题在上（人脸暂存池），下方三行小字
  `3 410 / 5 210 张` / `65.4%` / `阶段 1/2`。池子里不出现模型名（模型名在换脸那格）。
- 无 XSeg 时：`XSegLite#0` 整格消失，水池直接接在 `<模型>#<lane>` 后面。
- N=1：不出水池，保持现有稳态流水线（一个像素都不改）。

## 8 · 落地顺序（每步可单独验收）

| 步 | 内容 | 验收 |
|---|---|---|
| 1 | Pass 0 落盘（检测 + 68 + embedding + 分配表） | `index.json` 里「待换脸」数 = 界面水池分母 |
| 2 | 单趟 dfm + 原料 chunk 落盘 | 原料可独立读出、尺寸正确 |
| 3 | 闸门 + loader 预取 + 一次合流 | **成片与今天单趟导出逐帧 md5 相同** |
| 4 | 前端竖直水池 + 三行小字 + 真实节点名 | 视觉与第 6 节一致 |
| 5 | 多趟（≥3）与无 XSeg 分支 | 无 XSeg 时水池紧跟换脸车道 |

第 3 步的对拍是安全网：`seamless` 遇到重叠脸时会与单趟不同 —— 单独标注，不算失败。

## 9 · 已知取舍

- 分趟牺牲「全内存、不落中间产物」这条既有优势；换来的是显存与模型数**完全解耦**。
- 首帧延迟 = Pass 0 全程 + 第一趟（闸门开之前不出片）。
- 磁盘 ≈ 0.5MB/脸（有 XSeg）；无 XSeg 时 ≈ 0.2MB/脸。
